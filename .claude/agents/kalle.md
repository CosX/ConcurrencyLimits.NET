# C# Developer Mode

Always use latest stable .NET and C# features: file-scoped namespaces, records, pattern matching, primary constructors, collection expressions.

## Design Principles

- SOLID principles, dependency-injected designs
- Self-documenting code — minimize comments
- Keep diffs small; reuse code; avoid new layers unless needed

## Rules

- Don't edit auto-generated code (`/api/*.cs`, `*.g.cs`, `// <auto-generated>`).
- **Never put business logic in `src/api/`** — it belongs in `src/service/`.
- **Never use MediatR for commands/queries** — only for domain event dispatch via `IDomainEvent`.
- **Always use `OneOf<>` for feature results** — not exceptions for expected errors.
- **Always register new services** in the appropriate `ServicesConfiguration.cs`.
- **Always wire new endpoint groups** into the parent group's `MapXxxEndpoints` method.
- **Always search the codebase first** — find similar features and match the established pattern exactly.
- **Use primary constructors** for DI — no explicit backing fields.
- **Keep endpoints thin** — delegate to features, use mappers for transformation.

## Naming Conventions

| Element | Style | Example |
|---------|-------|---------|
| Classes/Interfaces | PascalCase | `CustomerService`, `ICustomerRepository` |
| Methods/Properties | PascalCase | `Execute`, `CustomerId` |
| Parameters/Locals | camelCase | `customerId`, `result` |
| Private fields | camelCase | `customer`, `logger` |
| Constants | PascalCase | `MaxRetryCount` |
| Async methods | **No** "Async" suffix | `GetCustomer()` not `GetCustomerAsync()` |

## Nullability

- Enable nullable reference types in all projects
- Null-forgiving (`!`) sparingly — prefer null checks (`is` over `==`)

## Exception Handling

- Validate inputs at public API boundaries — fail fast
- Never swallow exceptions or use them for control flow

## Logging

- Structured logging with message templates: `Log.LogInformation("Customer {CustomerId} retrieved", customerId)`
- Never log passwords, tokens, PII, or secrets

## CancellationToken

- **Use**: external API calls, user-cancellable ops, long-running background work
- **Skip**: simple CRUD, fast operations (<1s), atomic operations
